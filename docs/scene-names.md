## Pools

- `pool.avatar.1 .. pool.avatar.7`: Pre-placed hidden remote-player bodies (different Kenney mini skins), feet at the origin, forward -Z, animation on the pool object itself (autoplay idle; same clips as Player Avatar). Assign one per remote player: set_position/set_rotation + set_visible + play_animation/crossfade. Named pool.* so they never clash with the view's `avatar.<player id>` copies.

## Notes for game code

- Copies made with spawn_copy / spawn_copy_at_root do not animate and skinned meshes show their bind pose: the engine renames copied children `<copy>/<child>`, but animation track targets and skin joint paths still use the original child names. So animated things are used directly (`tpl.enemy.rig_brute`, `tpl.enemy.leviathan`, `tpl.trader_boat`, `pool.avatar.N`, survivors, Barnaby); `tpl.enemy.gloomfin/crawler/reef_crab` and `tpl.avatar` copies show a still rest pose until the engine copies fix the paths.
- Hidden lights do not count toward the light cap (32 on Balanced). Visible point lights in the scene: `smoking_rig.flare.light` only.
- No looping ambience in the scene: start it from code with `play_sound_looped("sfx/ocean_loop.wav", vol)` and `sfx/wind_loop.wav` (also `water_lap_loop.ogg`, `fire_loop.ogg` near campfires).
- The ocean surface is not in this scene (the view module owns it). Nothing here is named Ocean or Water.
- Shadow quality/reach is code-only (rusting.render_settings): Auto or Medium is a good default.
- Name tags for remote players: a rusting.hud with `follow` set to the avatar object, or egui.
